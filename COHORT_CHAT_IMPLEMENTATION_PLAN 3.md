# Cohort Chat – Implementation Plan

## 1. Objective
Build a *Cohort Chat* feature that lets a user choose a demographic/interest‐based group (the **cohort**) and ask natural-language questions. Responses are generated by synthesising relevant survey answers from respondents within that cohort.

## 2. Key Concepts

| Term | Description |
|------|-------------|
| **Cohort** | A saved or ad-hoc filter that selects a subset of survey respondents (e.g. *"Gen-Z Democrats"*). |
| **Cohort Query** | A request containing (1) the cohort filter and (2) the user's question. |
| **Knowledge Base** | The collection of survey responses that satisfy the cohort filter. |

## 3. Architecture Overview
1. **UI** (Next 15 + shadcn/ui) – New *Cohort Chat* page/tab following the standard layout in `LAYOUT_PATTERN.md`.
2. **API** – `POST /api/cohort/query` pipeline:
   - Validate user & cohort visibility.
   - Translate cohort filter → SQL (row-level filtering).
   - Retrieve matching answer IDs + text.
   - Vector similarity search with `text-embedding-3-small` (Pinecone, namespace *surveys*).
   - Prompt LLM for synthesis (OpenAI or local model).
3. **Data Layer** – Survey tables, optional `cohorts` table for saved filters.

```mermaid
flowchart TD
  A[User selects cohort & asks question]
  B[POST /api/cohort/query]
  C[Fetch cohort responses (SQL)]
  D[Vector search (Pinecone)]
  E[Top-K answers]
  F[LLM synthesis]
  G[Return answer + citations]
  A --> B --> C --> D --> E --> F --> G --> A
```

## 4. Database Changes
| Table | Change | Notes |
|-------|--------|-------|
| `survey_responses` | Ensure columns for demographics & meta are present and indexed. | e.g., `age_range`, `political_affiliation`, `income_bracket`, `interests` |
| `cohorts` | **New**: `id`, `name`, `filter_json`, `created_by`, `visibility` | Optional – enables reusable cohorts |

## 5. API Design
### 5.1 List Cohorts
`GET /api/cohorts` → Returns saved cohorts visible to the user.

### 5.2 Cohort Query
`POST /api/cohort/query`
```jsonc
{
  "cohort": {               // Saved cohort ID **or** inline filter
    "id": "uuid?",        // optional
    "filter": [            // inline example
      { "field": "age_range", "op": "IN", "value": ["18-24"] },
      { "field": "political_affiliation", "op": "=", "value": "Democrat" }
    ]
  },
  "question": "Why do you like Nike?",
  "topK": 20               // optional override
}
```
Response
```jsonc
{
  "answer": "…synthesised text…",
  "citations": [ { "responseId": 123, "score": 0.87 } ],
  "meta": { "sampleSize": 57, "model": "gpt-4o" }
}
```

## 7. Security & Privacy
1. Require auth; check cohort visibility and user rights.
2. Parameterised SQL to avoid injection.
3. Never return PII in `citations` or answers.
4. Rate-limit `/api/cohort/query` and log usage.

## 8. Performance & Cost
- Use Pinecone metadata filter if response set is >5k, else fetch IDs and local-filter.
- Cache `(cohort, question)` pairs (Redis) for 24 h.
- Stream LLM output for snappy UX.
